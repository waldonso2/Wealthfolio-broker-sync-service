# Wealthfolio Broker Sync

Service that fetches broker transactions and writes them, deduplicated, into a self-hosted Wealthfolio via its REST API. Installed as an LXC with one line in the Proxmox shell (community-scripts layout and engine); PVE Scripts Local can't list it, because its catalog only shows scripts from the official community-scripts database. A standalone service: user docs (README, UI texts) never point to another tool; CSV/PDF imports are only mentioned generically, as activities the sync recognises. The issue backlog is kept in `waldonso2/wealthfolio-importer-addon` (e.g. #43 new banks, #51/#52 comdirect).

## Commands

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install --require-hashes --only-binary :all: -r requirements.txt   # the locked versions users get
pip install --no-deps --no-build-isolation -e . && pip install pytest pytest-cov respx ruff mypy
pytest -q                 # all tests
ruff check src tests      # lint (incl. C901 complexity ≤ 15)
mypy src                  # types
shellcheck ct/*.sh install/*.sh deploy/setup.sh deploy/brokersync-reset-password deploy/brokersync-cli scripts/*.sh
scripts/lock.sh           # after changing a dependency in pyproject.toml (needs uv); --upgrade: newest versions
BROKERSYNC_DATA=./data brokersync serve --port 8090   # UI locally
BROKERSYNC_DATA=./data brokersync run                 # one sync
```

## Invariants (keep them)

- **Booking model** (keep it - CSV/PDF imports into the same accounts follow it, and the dedup layers rely on it): two-account model, every internal TRANSFER_OUT/TRANSFER_IN pair shares a `sourceGroupId`, BUY/SELL `amount = trade_final_cash(...)`, fee/tax in their own fields, tax refund = CREDIT/TAX_REFUND, cash activities carry **no asset** (quantity/unitPrice 1) - with an asset Wealthfolio books a TRANSFER_IN/OUT as a securities transfer that moves no money; `repair.py` fixes the `$CASH-<ccy>` ones versions before 0.3.6 created. Changes go into `mapping.py` and `test_mapping.py` together.
- **Comments are part of Wealthfolio's duplicate fingerprint.** Every activity ends in `[SYNC <broker>:<tx id>]`; never reword existing comment texts, or synced activities reappear as new.
- **Dedup layers:** state DB (`synced`), Wealthfolio's fingerprint ("Duplicate activity detected" → `Duplicate`, not an error), `dedup.ExistingIndex` for activities from CSV/PDF imports. Never require the same symbol there: an import books securities under the user's mapped ticker, the sync under the ISIN - trades match on share count + amount + time, dividends with another symbol only when unambiguous. Activities carrying our own `[SYNC …]` reference are *not* matched there: the whole transaction is re-sent so an interrupted run is completed.
- **Wealthfolio says what is booked, the user decides what comes back.** `state.synced` only decides what is *new*; every run compares the rest with Wealthfolio (`coverage.py`). Missing ones are listed, never re-created without the user's *Wieder anlegen* (a deletion may be on purpose); orphans are listed, never deleted. `ignored` transactions are never booked.
- **A transaction is marked synced only when all its activities exist.** Failures stay unmarked and are retried; a run with failures is not a "success", so the next run fetches from before it.
- **Adapters are read-only** (AC 7 of #35): no endpoint that trades, transfers or changes settings. The Scalable adapter calls only `sc` read commands and logs in with `--local-read-only`.
- **`sc` only from Scalable's signed release** (`sc_install.py`); never a build from source, a fork or another package source. The CLI's session files never stay on disk: temp dir per adapter, contents in the vault.
- **Bank-side cash of securities is never booked twice.** A giro booking that settles a depot trade or payout is `Kind.SECURITIES_CASH`: the sync only looks for the transfer leg the securities side (a PDF import of the statements, or a depot adapter) put on the cash account (`ExistingIndex.find_settlement`, ±0.02, ≤6 days). Unmatched ones are reported (`UNMATCHED_SECURITIES`), not marked synced, and keep the fetch window open (`State.oldest_open`) until they match.
- **Transfer patterns** (`Config.transfer_patterns`, UI *Überträge*) only apply to outbound money (WITHDRAWAL); inbound is always DEPOSIT.
- **Savings account** (optional third account, `BrokerConfig.savings_account_id`, adapters with `savings_label` - every `FintsAdapter`): its bookings carry `Transaction.account = SAVINGS` (ids `sav-…`) and go to `Accounts.savings`; its balance is a `CashBalance` with `account = SAVINGS` (stored as `<ccy>:savings`) compared with that account. A giro booking whose counterparty is the own savings IBAN is `own_transfer` (one TRANSFER_OUT/IN pair); its savings side names it in `pair`, is not booked and is marked with the pair's ids - unless the giro side was synced before (then it is booked on its own). `meta savings-account:<broker>` = the account read without failures; until then the savings account is read from the start date. Everything that lists a broker's activities uses `Accounts.ids`.
- **Abrufmodus** (#85, `Config.sync_mode`, page *Sicherheit*, for all brokers): `auto` keeps sessions and the timer fetches; `safe`: `Syncer.run` without `manual=True` (timer, CLI) contacts no broker and only reminds via ntfy, every fetch from the UI starts with a login (`AppContext.needs_login` → `/brokers/<key>/login?run=1`, "Alle abrufen" chains the logins in `session["run_queue"]`, then one run), and `_run_broker` ends the session afterwards whatever happened (`end_sessions` → `safety_state`: only `SAFETY_KEYS` - the lock-out guards - stay). Switching to `safe` ends all sessions at once.
- **A credential field with `ask=True` may stay empty** (#85; FinTS `pin`): the login asks for it (`Challenge("pin")`), it is registered with `redact` and kept in memory only (`AppContext.pins` → `Syncer.run(pins=...)`), never written to the vault, the state, a session blob or a log. Such a broker always fetches via the login, in either mode.
- **Never risk a bank lock-out:** after a rejected PIN an adapter sets `pin_rejected` in its session and refuses to contact the bank until the credentials are saved anew (`Vault.set_broker_credentials` clears the session). comdirect also locks after 5 TAN challenges without a correct TAN and after 3 wrong TANs: its adapter counts `open_challenges` (before each challenge request) and `wrong_tans` in the session and stops at `MAX_OPEN_CHALLENGES` / after `MAX_WRONG_TANS`; a scheduled run never opens a challenge for a TAN that has to be typed in, and never activates a push challenge before its status link says `AUTHENTICATED`.
- **Trade Republic events go through pytr's `Event.from_dict`** (the parser pytr's exports use), then `tr.to_transactions` maps them (trades with fee and tax, dividends net with withholding tax, Saveback as bonus-funded buy, …). Events pytr lists as informational (`events_known_ignored*`) and cancelled ones are skipped; everything else it can't book (corporate actions, securities transfers, private markets) is `UNKNOWN`. pytr is pinned (`pytr==…`): update it deliberately and re-run the contract case. Unknown payloads keep only eventType/title/subtitle/status and the amount (`betrag`), so the user can book them by hand.
- **Scalable** maps `sc broker transactions` (the same data as the Transactions Exporter userscript's CSV, so imports of it are recognised): only FILLED/SETTLED; depot-migration pairs (security out/in, same ISIN and shares, ≤7 days; cash `SWITCH-` deposit + equal withdrawal) are skipped; a security `SWAP_OUT` with its cash `SWAP_OUT` (fund swap) and a security leg out with value 0 plus a distribution of the same ISIN and day (certificate redemption) become a SELL; a cancelled distribution and its original always cancel out (an original synced already shows up as orphan on *Prüfung*); every run reads the whole history (`full_history`), details only for new transactions; other cancellations, unpaired security transfers, ELTIFs, negative interest and fee refunds are `UNKNOWN`. A distribution has no share count: the dividend gets quantity 1.
- **comdirect books only the depot, not the giro account:** the cash account receives the dividends (swept from the depot) and nothing else - trades carry `external_cash` (a BUY is preceded by a DEPOSIT of its cost on the cash account, a SELL followed by a WITHDRAWAL of its proceeds, `mapping.py`), other giro bookings are ignored, `get_cash` reports no balance. It books BUY/SELL from the depot transactions (`transactionValue` = gross) with the giro booking of type *Wertpapier* that settled them (right sign, −1…+6 days, costs ≥ 0 and < half the value, one naming the ISIN/WKN first): its amount is `net`, the difference `fee` (sales: fee and tax together - the API doesn't split them). That booking is consumed; a *Zinsen / Dividenden* booking is a DIVIDEND when it names a known security (ISIN, or WKN of a position), else `UNKNOWN`; interest and every other giro booking is not booked. A trade without settlement waits `UNSETTLED_DAYS`, then is `UNKNOWN`; depot transfers are `UNKNOWN`. Ids: `dep-<transactionId>`, `acc-<reference>` - never change them.
- **Deutsche Bank depot CSV** (`deutschebank_csv.py`): rows are stored without depot/account numbers; ids `dbcsv-<day>-<hash of day, type, ISIN, shares, amount>-<n>` - never change them. Dividende/Kauf/Verkauf are paid via the cash account (their giro booking is `SECURITIES_CASH` and matched in the same run: `_sync_tx` adds the cash legs of non-external trades/payouts to the index, settlements are processed last); *Eingang* with an amount and every Kauf/Verkauf before the earliest giro day read (`meta history-start:<broker>`) carry `external_cash`; a DIVIDEND never does, and `mapping.py` ignores `external_cash` for dividends - their money stays on the cash account; anything else is `UNKNOWN`.
- **Imports before the bank history** (`Syncer._before_history`, adapters that set `history_start` - FinTS): `meta history-start:<broker>` is the earliest giro day ever read (seeded once from the first successful run: start date, else `NO_TAN_DAYS` before it). Every cash TRANSFER_OUT/IN of an import (no `[SYNC`, not matched as a settlement) before it that sits within `MOMENT_SECONDS` of a BUY/SELL on the depot gets a DEPOSIT just before / WITHDRAWAL just after, id `pre-<activity id>` - never change it; dividends keep their money.
- **Opening positions** (`state.openings`, page *Prüfung*): a position the broker holds more of than Wealthfolio (last check) can be entered with date, price and fee; every run adds it as a BUY `start-<isin>-<day>` with `external_cash` (`Syncer._openings`), booked once like any transaction.
- **Neu aufsetzen** (`reset.py`, broker settings, confirmation required) deletes only activities carrying `[SYNC <broker>:` in the broker's two accounts and resets its state (`State.reset_broker`, keeps openings and assets).
- **Tax on imported dividends** (`Syncer._add_dividend_tax`): when a DIVIDEND with `tax > 0` matches an import's dividend whose tax is empty/0 (not the sync's own), only its `tax` field is updated (PUT, asset kept). Once per broker (`dividend-tax:<broker>` flag) the transactions matched before are re-read with details (`known_ids` without `existing` ones) and get the same treatment; the flag waits for a run without failures and without `adapter.incomplete` (Scalable's rate limit).
- **Unknown event types** become `Kind.UNKNOWN`: stored, listed in the UI, notified once — never dropped, never booked. *Unbekannt* offers a prefilled GitHub issue per booking (`views.report_url`, #86): only the masked payload, opened by the user, nothing sent by the service. `State.add_unknown` masks IBANs and long numbers in their payload (`redact.mask_numbers`; ISINs, dates and amounts stay).
- **Logos** (`logos.py`) are opt-in and send only ISINs to logo.dev. An asset with a custom logo is never touched; a logo the sync set is set once (`set`) - removed by the user, it stays removed; `none` is asked again after `RETRY_DAYS`. Nothing goes to Wealthfolio's static `ticker-logos/` (part of its build, overwritten by updates): only its logo API. A logo pass never changes a broker's result.
- **One broker failing never stops the others**; it is reported via ntfy with a link (`public_url` + path).
- **No test broker ships.** Test brokers live under `tests/` only (`fake_broker.py`); a broker the user can set up must be a real one - the old "Dummy" booked test data into real accounts. Anything that could still reach a real Wealthfolio as test data is marked **TEST** in every activity's comment.
- **Secrets only in the vault**, never in the config, logs, exceptions shown to the user, notifications, or the repo. Test data is fabricated — no real statements, names, IBANs or account numbers.
- **Nothing readable in `data/`, no key there** (#53): everything the service writes goes through `crypto` (sealed files) or SQLCipher; new files get mode 0600 (`crypto.write_atomic`, `crypto.open_lock`). The host key comes from systemd in production; `data/secret.key` exists only in development/tests and before `setup.sh` migrated it. `test_security.test_nothing_readable_in_data_after_a_run` scans `data/` and the log after a real run - extend its list when new data is stored. Never log the passphrase or its argon2id result; the unlock cache lives only in `/run`.
- **Re-encryption is crash-safe** (#91; `security.change_passphrase`, `security.rotate_host_key`, `security.recover`): every file of the data tier is written re-encrypted as `<name>.rekey` next to the old one (`state.db` as a copy - **never** `PRAGMA rekey` in place), then the journal `rekey.json` decides. A passphrase change switches when it writes the journal; a new host key switches when `setup.sh` stores the key (rotate-key only stages, `brokersync recover` swaps; the journal's check value, sealed with the new host key, tells which key is in use). `recover` runs before anything reads the data (`brokersync serve/run/migrate/recover`) and finishes or undoes; staged files without a journal are leftovers. Never replace the stored key before the staged files and the journal exist. `test_security` crashes at every step.
- **Master passphrase loss = data loss**, by design: no recovery path, no backdoor key. Changing it re-encrypts everything under the sync lock; the web app is rebuilt afterwards (`gate.reset()`).
- **Dependencies only at locked, hash-checked versions** (#58): `deploy/setup.sh` installs `requirements.txt` with `--require-hashes --only-binary :all:` (no sdist build code runs) and then the package with `--no-deps --no-build-isolation`. A new or changed dependency in `pyproject.toml` means running `scripts/lock.sh` in the same change; `test_packaging` fails otherwise. CI tests exactly these versions.
- **The install engine is pinned** (#61): `ct/wealthfolio-broker-sync.sh` sets `COMMUNITY_SCRIPTS_CORE_URL` to a commit of community-scripts/core, unconditionally (an `update` command written earlier still exports its old URL) - it runs as root on the Proxmox host. Move the pin only after reviewing core's changes (`core-watch.yml` opens an issue when main moved on). Backups are created under `umask 077`.
- **Dedup rules are shared with the addon** (#69): a change to `dedup.ExistingIndex`'s matching rules goes into `contract/dedup/cases.json` here and in the addon (`waldonso2/wealthfolio-importer-addon`, same path) in the same change; this copy is leading.
- **CI gates** (#70): `ruff` (incl. C901, max complexity 15) and `mypy src` must pass. Functions above the limit carry `# noqa: C901 (#NN)` naming the issue that splits them - never add one without an issue.
- **UI navigation** (#71): the header holds Übersicht, Prüfung, Unbekannt, Einstellungen; a new settings page goes into `SETTINGS_PAGES` (`web/context.py`), not into the header; a new page goes into the router of its area under `web/routes/` (a new router into `ROUTERS`). The pages *Überträge* and *Duplikate* are hidden for now (#84): their routers sit in `routes.HIDDEN` and their `SETTINGS_PAGES` entries are commented out; code and tests stay (tests use the `hidden_pages` fixture), and saved transfer patterns still apply. Table cells get `data-label` (their column name) so the tables stack on phones (#72). Dates and times only through the filters `day` (`TT.MM.JJJJ`) and `local` (`TT.MM.JJJJ HH:MM`, German time; UTC only in `<time datetime>`) - never `[:10]` or raw ISO (#73). An unknown booking's payload is shown through `views.describe_unknown` (new payload keys go into its key lists); raw JSON only folded.
- **UI languages** (#87): German (default, `Config.ui_language`, page *Darstellung*) and English. Every new UI text goes through `_("…")` in templates or `tr(request, "…")` / `translate` / `N_` in Python, with the German text as key and an entry in `i18n.EN` (`test_i18n` finds missing ones); dynamic parts are `{name}` params, never an f-string - a value (broker name, amount, foreign error text) is never translated. Flash messages are stored translated. Deliberately not translated: ntfy notifications, texts from adapters (challenge messages, `AdapterError`, credential field labels - often the bank's own wording), foreign error texts, log lines, activity comments in Wealthfolio (duplicate fingerprint) and `[SYNC …]` references, the GitHub report of an unknown booking (`views.report_url`), the unlock page (the config holding the language is locked then).
- **Look and layout** (#83): Wealthfolio's look - Flexoki colours (light/dark via `prefers-color-scheme`, or fixed by `Config.ui_theme` on page *Darstellung* → `data-theme` on `<html>`; the CSS keeps both selectors), Inter and Merriweather served from `web/static/fonts/` (OFL; the CSP allows nothing from outside, and no scripts: collapsing is `<details>`), cards; phone first, the main navigation is a tab bar at the bottom below 700 px. The overview shows one card per broker with a traffic light (`views.broker_light`: red = failed/login needed, yellow = something to look at, green, grey = never fetched) and folds details; its reasons link to where they are handled (login, *Unbekannt*, *Prüfung*), its only buttons are *Jetzt abrufen* and a gear for the broker's settings; no amounts there, only whether the balance matches (`saldo`: cash deviations of the last check); the last 3 runs, older ones folded. *Prüfung* shows everything of a broker in one card; explanations go into the folded "Was wird geprüft?", not above the tables; an opening already booked is no longer shown there.
- **`state.db` changes only by migration** (#77): `SCHEMA` stays the 0.13.x baseline; a new column or table is a new function appended to `state.MIGRATIONS` (never edit or reorder one that shipped) with a test on an old database. A `meta` key is only ever built through `meta_keys.py` - a new one is added there (with `per_broker`), never as an f-string elsewhere.
- **Every form field is checked on the server** (#33): new fields go through `web/inputs.py` (or a check of their own) before they reach the config, the vault or the state - the HTML `pattern` is only a help; numbers through `inputs.decimal` (finite, bounded - `Decimal` alone takes `Infinity`/`NaN`). Errors are pages of the UI (`app._error_pages`, #106): an unexpected one shows only an id that is in the log. Request bodies are capped in `gate.py` (`MAX_BODY`), also for the pages without a session.
- **First password only with the one-time setup code** (#89): `/setup-password` is not in `PUBLIC` (its POST needs the CSRF token) and checks the code `vault.new_setup_code` made - shown only on the console (`brokersync-cli setup-code`, `reset-ui-password`, the end of the install in `ct/`), its SHA-256 and expiry in the vault, never logged. Tests set the password with `tests/helpers.first_password`.
- **Every password check goes through `Throttle.attempt`** (#90, `web/gate.py`): UI password, master passphrase, setup code. It counts the attempt before the argon2id check (64 MiB) and allows at most `slots` checks at once; per client (IPv6 by /64), plus a global limit. `BROKERSYNC_TRUST_PROXY` (`serve.proxy_options`) is the only way `X-Forwarded-For` is believed.
- **Foreign error texts are masked where stored and shown** (#60): `State.finish_run` stores `redact.redact(message)`, templates show error texts through the `redact` filter; httpx/httpcore log only warnings (request URLs can carry tokens). GitHub Actions are pinned to commit SHAs.
- `ct/wealthfolio-broker-sync.sh` exports `COMMUNITY_SCRIPTS_URL` (this repo's raw `main`) **before** sourcing `community-scripts/core`'s `core/build.func`: the engine resolves `install/<slug>-install.sh` and writes the container's `update` command from it. Without it both point to community-scripts/ProxmoxVE. `test_packaging.py` checks this, and that the install line in the README matches.

## Adding a broker

1. `src/brokersync/adapters/<key>.py`: subclass `BrokerAdapter`, set `key`, `label`, `credential_fields`; implement `login` (raise `AuthRequired(Challenge(...))` when the user is needed), `complete_login`, `session_state`, the four getters, and `replay`.
2. Map every event type the broker has to a `Kind`; anything else → `Kind.UNKNOWN` with `raw_type` and a `raw` payload without personal data.
3. Register it in `adapters/__init__.py`.
4. Add fabricated contract cases in `tests/contract/<key>/` (see its README).

A bank that speaks FinTS needs no adapter of its own - only a profile, like `dkb.py`:

1. Subclass `FintsAdapter`; set `key`, `label`, `credential_fields = credential_fields(...)` (`blz=True` if the bank code differs per branch), `blz` (or leave it empty), `server`, and the names in messages (`bank`, `app`, `banking`).
2. Override `securities_pattern` / `interest_pattern` / `fee_pattern` only if the bank's posting texts differ; giro bookings of depot trades must become `SECURITIES_CASH`.
3. Never change `fints.to_transactions`' id scheme (content hash + counter): every synced booking would look new.
4. Register it, add a contract case with its own posting texts, and run `tests/test_fints.py` against it (add it to `PROFILES`).

## Releasing

Version lives in `pyproject.toml` and `src/brokersync/__init__.py` (tested to match) with a `CHANGELOG.md` section `## <version>`. The release workflow creates `v<version>` when the tag doesn't exist yet; install and update deploy the latest release. Propose a bump for every change to `src/`, `deploy/`, `ct/` or `install/`; docs/CI-only changes need none.
