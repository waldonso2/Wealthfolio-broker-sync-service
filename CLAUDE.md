# Wealthfolio Broker Sync

Service that fetches broker transactions and writes them, deduplicated, into a self-hosted Wealthfolio via its REST API. Installed as an LXC with one line in the Proxmox shell (community-scripts layout and engine); PVE Scripts Local can't list it, because its catalog only shows scripts from the official community-scripts database. A standalone service: user docs (README, UI texts) never point to another tool; CSV/PDF imports are only mentioned generically, as activities the sync recognises. The issue backlog is kept in `waldonso2/wealthfolio-importer-addon` (e.g. #43 new banks, #51/#52 comdirect).

## Commands

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install --require-hashes --only-binary :all: -r requirements.txt   # the locked versions users get
pip install --no-deps --no-build-isolation -e . && pip install --require-hashes --only-binary :all: -r requirements-dev.txt
pytest -q                 # all tests
ruff check src tests      # lint (incl. C901 complexity ≤ 15)
mypy src                  # types
shellcheck ct/*.sh install/*.sh deploy/setup.sh deploy/brokersync-reset-password deploy/brokersync-cli deploy/brokersync-autoupdate scripts/*.sh
scripts/lock.sh           # after changing a dependency in pyproject.toml or requirements-dev.in (needs uv); --upgrade: newest
pip-audit -r requirements.txt --require-hashes --disable-pip   # known vulnerabilities (CI job audit)
BROKERSYNC_DATA=./data brokersync serve --port 8090   # UI locally
BROKERSYNC_DATA=./data brokersync run                 # one sync
```

## Invariants (keep them)

- **Booking model** (keep it - CSV/PDF imports into the same accounts follow it, and the dedup layers rely on it): two-account model, every internal TRANSFER_OUT/TRANSFER_IN pair shares a `sourceGroupId`, BUY/SELL `amount = trade_final_cash(...)`, fee/tax in their own fields, tax refund = CREDIT/TAX_REFUND, cash activities carry **no asset** (quantity/unitPrice 1) - with an asset Wealthfolio books a TRANSFER_IN/OUT as a securities transfer that moves no money; `repair.py` fixes the `$CASH-<ccy>` ones versions before 0.3.6 created. Changes go into `mapping.py` and `test_mapping.py` together.
- **Comments are part of Wealthfolio's duplicate fingerprint.** Every activity ends in `[SYNC <broker>:<tx id>]`; never reword existing comment texts, or synced activities reappear as new.
- **Dedup layers:** state DB (`synced`), Wealthfolio's fingerprint ("Duplicate activity detected" → `DuplicateActivity`, not an error), `dedup.ExistingIndex` for activities from CSV/PDF imports. Never require the same symbol there: an import books securities under the user's mapped ticker, the sync under the ISIN - trades match on share count + amount + time, dividends with another symbol only when unambiguous. Of several candidates the nearest in time wins (then the closest amount), and two currencies never match (#100). Activities carrying our own `[SYNC …]` reference are *not* matched there: the whole transaction is re-sent so an interrupted run is completed.
- **Wealthfolio says what is booked, the user decides what comes back.** `state.synced` only decides what is *new*; every run compares the rest with Wealthfolio (`coverage.py`). Missing ones are listed, never re-created without the user's *Wieder anlegen* (a deletion may be on purpose) - but one whose booking an import holds (`ExistingIndex`, never an activity with a `[SYNC` reference or one the state links to another transaction) is linked to it first (`Syncer._relink`): Wealthfolio may have taken every leg for a duplicate of the import, leaving no id to store; orphans are listed, never deleted. `ignored` transactions are never booked.
- **A transaction is marked synced only when all its activities exist.** Failures stay unmarked and are retried; a run with failures is not a "success", so the next run fetches from before it.
- **Adapters are read-only** (AC 7 of #35): no endpoint that trades, transfers or changes settings. The Scalable adapter calls only `sc` read commands and logs in with `--local-read-only`.
- **`sc` only from Scalable's signed release** (`sc_install.py`); never a build from source, a fork or another package source. The CLI's session files never stay on disk: temp dir per adapter, contents in the vault. `sc` runs through `brokersync.sandbox` (#93): Landlock - it reads the system and its own directory, writes only its temp dir, never `data/`, `/run/credentials` or the unlock cache - and an environment of only `PASS_ENV` plus its own paths (never `CREDENTIALS_DIRECTORY` or `BROKERSYNC_*`); the units allow `@sandbox` for it. pytr is updated only after reading its diff (`pytr==` pin, contract case run again).
- **Bank-side cash of securities is never booked twice.** A giro booking that settles a depot trade or payout is `Kind.SECURITIES_CASH`: the sync only looks for the transfer leg the securities side (a PDF import of the statements, or a depot adapter) put on the cash account (`ExistingIndex.find_settlement`, ±0.02, ≤6 days). Unmatched ones are reported (`UNMATCHED_SECURITIES`), not marked synced, and keep the fetch window open (`State.oldest_open`) until they match.
- **Transfer patterns** (`Config.transfer_patterns`, UI *Überträge*) only apply to outbound money (WITHDRAWAL); inbound is always DEPOSIT.
- **Savings account** (optional third account, `BrokerConfig.savings_account_id`, adapters with `savings_label` - every `FintsAdapter`): its bookings carry `Transaction.account = SAVINGS` (ids `sav-…`) and go to `Accounts.savings`; its balance is a `CashBalance` with `account = SAVINGS` (stored as `<ccy>:savings`) compared with that account. Such a broker always fetches via the login, in either mode.
- **Never risk a bank lock-out:** after a rejected PIN an adapter sets `pin_rejected` in its session and refuses to contact the bank until the credentials are saved anew (`Vault.set_broker_credentials` clears the session). Sessions are written back only through `Vault.store_session`: if another process wrote one since the adapter read it (web login and timer at once), the higher `open_challenges`/`wrong_tans` and a `pin_rejected` win; an emptied session (credentials saved anew) wins over the old login. Events pytr lists as informational (`events_known_ignored*`) and cancelled ones are skipped; a tax correction that takes money is a TAX, a `REFERRAL_*` with money a BONUS, a *Wertlos* write-off a SELL at 0 (no transfers, `mapping.py`); everything else it can't book (other corporate actions, dividend reinvestments - pytr reads no share count -, securities transfers, private markets) is `UNKNOWN`. pytr is pinned (`pytr==…`): update it deliberately and re-run the contract case. - **Scalable** maps `sc broker transactions` (the same data as the Transactions Exporter userscript's CSV, so imports of it are recognised): only FILLED/SETTLED; depot-migration pairs (security out/in, same ISIN and shares, ≤7 days; cash `SWITCH-` deposit + equal withdrawal) are skipped; a security `SWAP_OUT` with its cash `SWAP_OUT` (fund swap) and a security leg out with value 0 plus a distribution of the same ISIN and day (certificate redemption) become a SELL; a cancelled distribution and its original always cancel out (an original synced already shows up as orphan on *Prüfung*); every run reads the whole history (`full_history`), details only for new transactions; other cancellations, unpaired security transfers, ELTIFs, negative interest and fee refunds are `UNKNOWN`. A distribution has no share count: the dividend gets quantity 1.
- **comdirect books only the depot, not the giro account:** the cash account receives the dividends (swept from the depot) and nothing else - trades carry `external_cash` (a BUY is preceded by a DEPOSIT of its cost on the cash account, a SELL followed by a WITHDRAWAL of its proceeds, `mapping.py`), other giro bookings are ignored, `get_cash` reports no balance. It books BUY/SELL from the depot transactions (`transactionValue` = gross) with the giro booking of type *Wertpapier* that settled them (right sign, −1…+6 days, costs ≥ 0 and < half the value, one naming the ISIN/WKN first): its amount is `net`, the difference `fee` (sales: fee and tax together - the API doesn't split them). That booking is consumed; a *Zinsen / Dividenden* booking is a DIVIDEND when it names a known security (ISIN, or WKN of a position), else `UNKNOWN`; interest and every other giro booking is not booked. A trade without settlement waits `UNSETTLED_DAYS` (below `sync.OVERLAP`, so it is reported while still fetched), then is `UNKNOWN`; a reversed dividend (negative *Zinsen / Dividenden*) and depot transfers are `UNKNOWN`. Ids: `dep-<transactionId>`, `acc-<reference>` - never change them.

The page *Broker* (`/broker`) shows one card per broker with a traffic light (`views.broker_light`: red = failed/login needed, yellow = something to look at, green, grey = never fetched) and folds details; its reasons link to where they are handled (login, *Unbekannt*, *Prüfung*), its only buttons are *Jetzt abrufen* and a gear for the broker's settings; no amounts there, only whether the balance matches (`saldo`: cash deviations of the last check); the last 3 runs, older ones folded; above them, while a run goes on, its broker and step (`aria-live`), and for a new setup a checklist (#110) that can be hidden once done (`meta` `checklist-hidden`). *Prüfung* shows everything of a broker in one card; explanations go into the folded "Was wird geprüft?", not above the tables; an opening already booked is no longer shown there.
- **One database connection per thread** (`State.db` is a thread-local property, #101): the web UI's thread pool never shares a transaction. `crypto.write_atomic` writes through a temp file of its own (`mkstemp`), so two writers of one file can't truncate each other; `config.save` takes `secrets.lock` like the vault, so it can't race a re-encryption, and the UI changes the config only through `AppContext.update` → `config.update` (read, change, write under that lock, #117 - never `cfg()`, change, save); every write to `state.db` goes through `State._writing` under `state.WRITES`, which a passphrase change holds, and a write after the file was re-encrypted under it raises `StateReplaced` instead of landing in the old file (#120); `Gate.reset` closes the old app's connections. The broker start date is midnight German time (`sync.BERLIN`, #108). Moments from Wealthfolio or the state are parsed only by `model.when` (always UTC; no zone = UTC, a bare day = its midnight, #119).
- **`state.db` changes only by migration** (#77): `SCHEMA` stays the 0.13.x baseline; a new column or table is a new function appended to `state.MIGRATIONS` (never edit or reorder one that shipped) with a test on an old database. A `meta` key is only ever built through `meta_keys.py` - a new one is added there (with `per_broker`), never as an f-string elsewhere.
- **An unofficial interface needs the user's yes** (#112): an adapter with `consent` (Trade Republic, N26) can't save credentials or start a login (`start_login`, `_plan_window`) until `BrokerConfig.consented`; brokers set up before 0.23.0 count as agreed (`Syncer._consent_existing`). The FinTS product id is the service's own, registered with the Deutsche Kreditwirtschaft: `fints.product_id()` decodes `_REGISTERED` (XOR with a SHA-256 pad, so no search finds it - obfuscation, not encryption; new value via `scripts/obfuscate_product_id.py`) and registers it with `redact`; never write it in plain text anywhere (`test_fints` scans the repo). A user's own id saved before keeps working until the credentials are saved anew.
- **No C901 exceptions left** (#80): ruff's complexity limit 15 holds everywhere; the functions #80 named are split (`mapping._Booking`, `reconcile._cash_deviations`/`_stray_cash`/`_position_deviations`, `audit._moments`/`_lonely`, the FinTS account lookup over `_upd`/`_kind`, …). A new exception needs an issue.
- **Every form field is checked on the server** (#33): new fields go through `web/inputs.py` (or a check of their own) before they reach the config, the vault or the state - the HTML `pattern` is only a help; numbers through `inputs.decimal` (finite, bounded - `Decimal` alone takes `Infinity`/`NaN`). A form is checked completely before anything of it is saved; a form with errors comes back with status 422, what was typed (never a secret) and each error at its field (`_forms.html`: `invalid`/`error`, `aria-describedby`, #103) - the broker form does so, others still redirect with a flash (`role="alert"` for errors). Anything that can take longer than a moment (a fetch, *Neu aufsetzen*, logos, the account check of *Prüfung*) runs as a background job (`overview.start_job`/`launch`, one at a time, its result the next page's flash, #104); the overview shows a run's broker and step from `meta` `progress` and refreshes every 10 s, never faster. Errors are pages of the UI (`app._error_pages`, #106): an unexpected one shows only an id that is in the log. Request bodies are capped in `gate.py` (`MAX_BODY`), also for the pages without a session.
- **First password only with the one-time setup code** (#89): `/setup-password` is not in `PUBLIC` (its POST needs the CSRF token) and checks the code `vault.new_setup_code` made - shown only on the console (`brokersync-cli setup-code`, `reset-ui-password`, the end of the install in `ct/`), its SHA-256 and expiry in the vault, never logged; a form error answers with the page itself (422), never a redirect carrying the code (V-01 of #85), and a damaged entry counts as expired. Tests set the password with `tests/helpers.first_password`. The session carries `vault.session_tag` of the password hash and the session version `ui_session_gen` (#96): logout, a password change and *Alle anderen Sitzungen beenden* raise the version, so a copied cookie or one of an earlier password signs in nobody; a session ends after `IDLE_SECONDS` (30 min) idle and `MAX_SECONDS` (12 h) at all, and changing credentials, *Neu aufsetzen* and the fetch mode ask for the password again after `REAUTH_SECONDS` (`AppContext.reconfirm`). New passwords and passphrases are refused when `vault.weak_password` (the package's `common-passwords.txt`). No access log (a URL can carry the code).
- **Every password check goes through `Throttle.attempt`** (#90, `web/gate.py`): UI password, master passphrase, setup code. It counts the attempt before the argon2id check (64 MiB) and allows at most `slots` checks at once; per client (IPv6 by /64), plus a global limit. `BROKERSYNC_TRUST_PROXY` (`serve.proxy_options`) is the only way `X-Forwarded-For` is believed.
- **Logs and metrics** (OPS-04 of #85): `BROKERSYNC_LOG_FORMAT=json` swaps the formatter (`cli.JsonFormatter`), the redact filter stays on every handler; `GET /metrics` (Prometheus text from `state.runs` - counts, timestamps, outcomes, never amounts or names) needs the UI login or `Authorization: Bearer $BROKERSYNC_METRICS_TOKEN` (≥ 32 characters, `app._metrics_token`).
- **Foreign error texts are masked where stored and shown** (#60): `State.finish_run` stores `redact.redact(message)`, templates show error texts through the `redact` filter; httpx/httpcore log only warnings (request URLs can carry tokens). GitHub Actions are pinned to commit SHAs. The CI jobs `secrets`, `workflows` and `dependency-review` call the shared workflows of `waldonso2/quality-kit` (pinned to the commit of its tag `v1`); a stricter rule there comes as a new major tag and is adopted here by moving the pin.
- `ct/wealthfolio-broker-sync.sh` exports `COMMUNITY_SCRIPTS_URL` (this repo's raw `main`) **before** sourcing `community-scripts/core`'s `core/build.func`: the engine resolves `install/<slug>-install.sh` and writes the container's `update` command from it. Without it both point to community-scripts/ProxmoxVE. `test_packaging.py` checks this, and that the install line in the README matches.

## Adding a broker

1. `src/brokersync/adapters/<key>.py`: subclass `BrokerAdapter`, set `key`, `label`, `credential_fields`; implement `login` (raise `AuthRequired(Challenge(...))` when the user is needed), `complete_login`, `session_state`, the four getters, and `replay`.
2. Map every event type the broker has to a `Kind`; anything else → `Kind.UNKNOWN` with `raw_type` and a `raw` payload without personal data.
3. Register it in `adapters/__init__.py`.
4. Add fabricated contract cases in `tests/contract/<key>/` (see its README).

A bank that speaks FinTS needs no adapter of its own - only a profile, like `dkb.py`:

1. Subclass `FintsAdapter`; set `key`, `label`, `credential_fields = credential_fields(...)` (`blz=True` if the bank code differs per branch), `blz` (or leave it empty), `server`, and the names in messages (`bank`, `app`, `banking`).
2. Override `securities_pattern` / `interest_pattern` / `fee_pattern` only if the bank's posting texts differ; giro bookings of depot trades must become `SECURITIES_CASH`.
3. Never change `fints.to_transactions`' id scheme (content hash + counter): every synced booking would look new.
4. Register it, add a contract case with its own posting texts, and run `tests/test_fints.py` against it (add it to `PROFILES`).

## Releasing

Languages of the documents: README, ARCHITECTURE and UI texts German (the UI also English, #87); CLAUDE.md, CHANGELOG, code and comments English. The README is short (what it does, the diagram of companion, Wealthfolio and X-Ray addon, install with Proxmox or Docker, setup, daily table, security in brief); details go into `docs/BANKEN.md`, `docs/FUNKTIONEN.md`, `docs/BETRIEB.md`. The README describes only the current version: no older version numbers of the service, no notes about what earlier versions did or how to come from them (the owner's rule until they say otherwise; history goes into the CHANGELOG).

Version lives in `pyproject.toml` only (`brokersync.__version__` reads the installed metadata - after a bump, `pip install --no-deps --no-build-isolation -e .` again) with a `CHANGELOG.md` section `## <version>`. The release workflow creates `v<version>` when the tag doesn't exist yet; install and update deploy the latest release. Propose a bump for every change to `src/`, `deploy/`, `ct/` or `install/`; docs/CI-only changes need none.
